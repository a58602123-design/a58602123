## 現在的生產機制

週報仍由操作環境裡的 Python 直接寫檔。CSV 用 `shutil.copy2` 複製；`summary.json`、`history_8w.json`、`lights.csv` 直接寫出；三張圖先畫進週報目錄，再把位元組寫回工作目錄。

2026-11-15 的驅動是 `scripts/weekly_update_20261115.py`。它用 `SourceFileLoader` 載入工作目錄裡的兩支腳本：

- `upgrade_v11_visuals.py` 的 `compute_all()`、`write_csv()`：計分與 `lights.csv` 欄位
- `regen_charts_mobile.py` 的 `chart_lights`、`chart_compare`、`chart_trend`：手機大字圖

規則、門檻與綠區代表值寫在 `scripts/upgrade_v11_visuals.py` 的 `score_l01`–`score_l11` 與 `NORMAL`。維持這些函式的原樣。

驅動程式裡的路徑與日期是寫死的：

| 名稱 | 值 |
|---|---|
| 工作目錄 `ROOT` | `/workspace/fred-11lights` |
| 共用區 `SHARED` | `/workspace/shared-tasks/金融危機11燈` |
| 當週暫存 `RAW_IN` | `/tmp/fred-11lights-20261115` |
| 對照週 | `週報/2026-11-08` |
| 產出週 | `2026-11-15` |

`ROOT` 下面要有 `upgrade_v11_visuals.py` 與 `regen_charts_mobile.py`。驅動程式讀的是這兩個絕對路徑，不是本儲存庫裡的 `financial-11lights/scripts/`。

## 放上 GitHub 之後，排程仍然不讀這裡

這個目錄是匯入下來的快照，供人閱讀與核對。執行中的週日流程沒有 clone、pull 或 push，也不會改去讀 GitHub。把檔案放進這個儲存庫，不會讓排程自動同步，也不會改已在跑的週報作業或 Canvas。

要沿用原本那條生產路徑，機器上仍須保留上表的目錄與檔案。本匯入沒有改那些路徑，也沒有把腳本改成從儲存庫根目錄執行。直接在本儲存庫跑那三支寫死路徑的腳本會失敗；實測紀錄在 USAGE 與 VALIDATION。

## 門檻（對照用）

分數以程式為準。綠 = 0、黃 = 1、紅 = 2。總分 0–22：0–3 正常、4–7 留意、8–12 警戒、13–22 危機。

| 燈 | 序列與算法 | 綠 / 黃 / 紅 | 綠區代表值 |
|---|---|---|---|
| L01 殖利率曲線 | `T10Y2Y` 水準 | `>0.20` / `≥0` / 其餘 | +0.30% |
| L02 SOFR 利差 | `(SOFR−EFFR)×100` bps | `<5` / `≤15` / 其餘 | 2.5 bps |
| L03 Fed 流動性 | `WLCFLPCL/1000`，十億美元 | `<5` / `≤25` / 其餘 | $2.5B |
| L04 高收益債利差 | `BAMLH0A0HYM2` | `<4.5` / `≤6` / 其餘 | 3.00% |
| L05 金融壓力 | `STLFSI4` | `<0` / `≤1` / 其餘 | −0.50 |
| L06 VIX | `VIXCLS` | `<20` / `≤30` / 其餘 | 15.0 |
| L07 美元趨勢 | `DTWEXAFEGS` 的 20 日均線，相對再往前 20 個均線值的漲幅百分比，不年化 | `<1.0` / `≤2.5` / 其餘 | +0.50% |
| L08 薩姆規則 | `SAHMCURRENT` | `<0.3` / `<0.5` / 其餘 | 0.15% |
| L09 初領失業金 | `ICSA` 四週均線相對先前約 26 筆四週均線低點的增幅 | `<10` / `≤20` / 其餘 | +0.0% |
| L10 實質薪資 | `CES0500000003/CPIAUCSL` 月頻年增率 | `>0.5` / `≥−0.5` / 其餘 | +1.00% |
| L11 標普回撤 | `SP500` 最近最多 252 個交易日的高點回撤 | `<10` / `≤20` / 其餘 | 0.0% |
